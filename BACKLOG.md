# Backlog

Things we want to fix or add in the future, roughly in the order we'd tackle them. When you start on an item, open an issue or PR and link it here; remove the item once it's merged.

## Bugs and rough edges

### Renaming an icon fails the PR check
Renaming `icons/foo/` to `icons/bar/` touches two icon folders, so `check_icon_pr.py` reports "This PR changes several icons" and the check fails. Renames are legitimate.

**Proposal:** treat "one folder removed + one folder added, with the old `devicon.json` entry renamed" as a single-icon PR. The check-bot already labels these `release: major`.

### Renamed or removed icons stay in the font
The build only rebuilds glyphs of new or changed icons. Glyphs of icons that were renamed or removed from `devicon.json` are never deleted from `icomoon.json`, so they stay in the font and keep a CSS class (for example `framermotion` today).

**Proposal:** before uploading to icomoon.io, remove glyphs whose icon no longer exists in `devicon.json`, and let the codepoint guard allow exactly those removals. This is a breaking change for anyone using the old class, which is why renames and removals are labelled `release: major`.

### Codepoint guard message counts one glyph too many
`verify_glyph_codes` prints "all N existing glyphs that weren't rebuilt kept theirs" using the total glyph count, so N includes the rebuilt glyphs. Only the message is wrong, not the check.

**Proposal:** count only the glyphs that weren't rebuilt.

### Node 20 deprecation warnings
Workflow runs warn that `actions/checkout@v4`, `actions/setup-python@v5`, `actions/setup-node@v4`, `actions/upload-artifact@v4`, `actions/github-script@v7` and others target Node 20. GitHub will eventually stop supporting them.

**Proposal:** move each action to its current major version and re-test the PR and release workflows.

## Bots

### One bot comment per PR instead of a new comment on every run
The check-bot and peek-bot post a new comment each time they run, so long PRs collect many outdated comments.

**Proposal:** merge `post_check_icon_pr_comment.yml` and `post_peek_screenshot.yml` into one workflow that keeps a single comment up to date (check results, rename notice, peek screenshots).

### Make peeking more deliberate
- Maintainers can approve and merge before the peek-bot has posted its screenshots. Consider requiring the peek result before merging.
- The peek-bot runs on every push. Consider peeking only when a PR is opened (non-draft, icon PR) or when the `bot:peek` label is added.

## Automation clean-up

The automation grew over several years and has a lot of duplication. Planned as a series of small PRs, each tested on a fork:

1. **Remove dead code**: unused scripts and functions.
2. **One place that works out "what changed"**: today the PR check, the build, the release check and the release notes each compute it differently (Python, Bash and JavaScript embedded in YAML). Validate `devicon.json` with the existing `devicon-schema.json` instead of hand-written checks.
3. **Simplify the icomoon.io automation**: one Selenium class instead of three, on a current Selenium version. This removes the Selenium 4.1.0 pin and the geckodriver binaries committed to the repo, and replaces the fragile icomoon.io UI selectors where possible.
4. **Fewer workflows**: check + peek in one PR workflow, and one workflow for comments, labels and renames.
5. **Release logic in Python with tests**: move the version bump and release notes out of `build_weekly.yml` into a tested script.

## Website

### Sort icons by release date and last updated
Add a "Sort by" dropdown next to the search box on devicon.dev: *Name (A–Z)* (default), *Newest* (the release an icon first shipped in) and *Recently updated*. Optionally show "Released in vX.Y.Z" for the selected icon.

**Proposal:**
- A script generates `devicon-history.json` from git history: for each icon, the first release containing it and the release with its last real change. Ignore the weekly `build:` commits and bulk commits that touched many icons at once (for example the 2021 SVGO optimization).
- Keep it as a separate generated file (not part of the hand-edited `devicon.json`), regenerated by the weekly build so it ships with every release.
- The site loads it next to `devicon.json` and hides the dropdown if the file is missing, so older releases keep working.
- Known limitation: renaming an icon's folder resets its history.

## Longer term

### Build the font locally instead of through icomoon.io
The build depends on driving the icomoon.io web app with Selenium, which is slow and breaks when the site changes.

**Proposal:** build the font with Node tools (`svgicons2svgfont` → `svg2ttf` → `ttf2woff` / `ttf2eot`), keeping the existing glyphs and codepoints from `icomoon.json` and normalizing new SVGs to the same 1024-unit grid. Prototype first and compare the output with the current fonts. This would also allow PR previews made from the real font instead of icomoon.io screenshots.
